# 解析服务页面设计

## 概述

将现有的"设置"页面重构为"解析服务"页面，用于展示系统中配置的解析视频服务、测速结果，并支持手动测速功能。

## 页面结构

- **页面标题**：解析服务
- **右上角**：全部测速按钮（手动触发两轮测试）

## 列表字段

| 字段 | 说明 |
|------|------|
| # | 序号 |
| 名称 | 解析服务名称 |
| 链接 | URL，超链接形式（点击跳转），显示省略 |
| 状态 | 两轮测试结果，格式：`第一轮延迟 / 第二轮延迟`，如 `0.3s / 2.1s`、`✗ / ✗`、`0.2s / ✗` |
| 操作 | 复制（复制链接到剪贴板）、测速（手动触发单条两轮测试） |

## 状态说明

- 通过显示延迟：如 `0.3s`
- 失败显示 `✗`
- 两轮都通过：`0.3s / 2.1s`
- 两轮都失败：`✗ / ✗`
- 第一轮通过，第二轮失败：`0.2s / ✗`
- 测速中显示 loading 动画

## 两轮测试逻辑

1. **第一轮（httpx）**：快速 HTTP 请求，检测解析服务是否响应
2. **第二轮（Playwright）**：浏览器模拟真实解析，检查是否获取到 m3u8 视频

## 功能点

- **全部测速**：触发所有解析服务的两轮测试
- **单条测速**：对单个解析服务触发两轮测试
- **复制链接**：将解析服务 URL 复制到剪贴板
- **测速中状态**：操作列显示 loading，状态列显示进度

## 视觉风格

- 深色主题，与现有页面保持一致
- 列表布局，一行一个解析服务
- 响应式：窄屏幕时链接列简化显示

## 技术实现

- 复用现有的 `/parse-configs` API
- 新增后端 API 支持单条解析服务测速（两轮）
- 复用现有的 `test_parse_config` 和 `test_parse_config_browser` 函数

## 路由变更

- 路由 `/settings` 改为 `/parsers` 或保持 `/settings` 但变更页面内容
- 路由名称展示为"解析服务"
